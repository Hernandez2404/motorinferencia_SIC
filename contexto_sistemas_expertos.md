        reglas_aplicables = []

            # a) No repetir reglas ya disparadas

                # Verificar si la regla se aplica (todos los antecedentes son hechos)

            for _, regla in reglas_aplicables:

        else:
            print("- Ninguna")

            break # No hay reglas aplicables, detener la inferencia

        reglas_aplicables.sort(key=lambda item: len(item[1]["antecedentes"]), reverse=True)

        # c) Seleccionar aquellas que tengan antecedentes recién agregados

        # Seleccionar la primera regla aplicable después de la resolución de conflictos
        indice_regla_seleccionada, regla_seleccionada = reglas_aplicables[0]

## 2. Presentación: *Sistemas Expertos*

### 2.1 Representación del conocimiento

La representación del conocimiento y el razonamiento es un área de la IA cuyo objetivo es representar el conocimiento de forma que facilite la **inferencia** (sacar conclusiones). Implica definir los símbolos para representar el problema y la forma de usarlos para inferir nuevo conocimiento. Aborda la descripción formal del dominio, sus objetos y las relaciones entre ellos.

### 2.2 Sistemas de producción: fundamentos y componentes

Un **sistema de producción** es un modelo basado en reglas `SI condición ENTONCES acción` para describir un dominio de forma formal y operar sobre objetos y relaciones.

**Propósito**
- Representar el conocimiento del dominio de manera explícita.
- Describir formalmente el dominio mediante reglas.
- Facilitar la inferencia sobre la información disponible.
- Deducir nuevo conocimiento a partir de hechos y reglas.

**Componentes principales**
- **Memoria de trabajo / Base de hechos**: hechos iniciales y deducidos.
- **Base de conocimiento / Base de reglas**: reglas del dominio.
- **Interpretador o motor de inferencia**: examina el estado actual y determina qué reglas pueden ejecutarse.
- **Resolución de conflictos**: selecciona una regla cuando hay varias posibles.
- **Acción / actualización**: inserciones, modificaciones o eliminaciones en la memoria de trabajo.

**Ciclo básico del interpretador**
1. **Emparejamiento** (reconocimiento): identifica qué reglas pueden ejecutarse con el estado actual (compara patrones de las reglas con la memoria de trabajo).
2. **Resolución de conflictos** (selección): elige una regla entre las satisfechas y ejecuta su parte ENTONCES.
3. **Acción** (ejecución): ejecuta la regla y actualiza la memoria de trabajo (también podrían añadirse nuevas reglas).
4. **Detener / repetir**: si se cumple la condición de parada se detiene; si no, se repite el ciclo.

> La **estrategia de control** especifica la forma de resolver conflictos.

**Idea clave:** un sistema de producción combina hechos, reglas y un mecanismo de inferencia para resolver problemas sistemáticamente.

Fuentes citadas: Rich & Knight (2004); Rolston (1998); Russell & Norvig (2003); Bigus & Bigus (2001).

### 2.3 Resolución de conflictos

**Conjunto de conflicto:** conjunto de reglas aplicables cuyos antecedentes están satisfechos por la base de hechos actual.

**Momento de la decisión:** detectar reglas aplicables → formar el conjunto de conflicto → aplicar estrategia de resolución → disparar una regla.

| Rolston | Bigus |
|---|---|
| 1. Seleccionar la primera regla del conjunto | 1. Descartar todas las instancias que ya se hayan disparado |
| 2. Seleccionar la regla con mayor especificidad o número de cláusulas antecedentes | 2. Seleccionar la regla cuyos antecedentes se agregaron más recientemente a la memoria de trabajo |
| 3. Seleccionar la regla que se refiere a datos más recientemente cambiados | 3. Seleccionar la regla más específica (lado derecho más detallado) |
| 4. No adicionar reglas ejecutadas en el ciclo anterior | 4. Seleccionar una regla arbitrariamente (desde el conjunto de conflictos) |
| 5. Seleccionar una regla al azar | |

**Propia estrategia (propuesta en clase)**
1. 4 Bigus o 1 Rolston
2. Mayor número de relevantes
3. 2 Bigus
4. 3 Bigus
5. 3 Rolston
6. 5 Bigus

**Criterios para diseñar una estrategia propia**
- Relevancia para el objetivo del sistema.
- Costo/beneficio computacional frente a la calidad de la inferencia.
- Novedad de la información (priorizar información reciente cuando sea relevante).
- Evitar ciclos y repeticiones inútiles.

**Algoritmo Rete (conflictos)**
- **Refracción**: una regla solo puede usarse una vez para cada conjunto de hechos vigente.
- **Nuevos hechos primero**: usar reglas que utilizan los hechos agregados más recientemente.
- **Especificidad**: usar la regla más específica.
- **Prioridades**: asignar prioridades a las reglas (p. ej., MYCIN).

**Idea clave:** la resolución de conflictos controla el orden del razonamiento y puede cambiar la eficiencia y los resultados del sistema.

### 2.4 Encadenamiento hacia adelante (guiado por los hechos)

**Cuándo se usa:** se parte de hechos iniciales conocidos y se buscan nuevas conclusiones; útil cuando no se conoce la meta exacta; explora las consecuencias de la información disponible.

**Algoritmo básico**
1. Cargar reglas y hechos iniciales.
2. Buscar coincidencias entre reglas y hechos actuales.
3. Formar el conjunto de conflictos.
4. Seleccionar una regla (estrategia de elección).
5. Dispararla y actualizar la base de hechos.
6. Repetir hasta alcanzar la meta o hasta que no haya más reglas aplicables.

(Detección → Elección → Aplicación)

**Ejemplo paso a paso**

Reglas: `R1: p ∧ q → s`, `R2: r → t`, `R3: s ∧ t → u`, `R4: s ∧ r → v`
Hechos iniciales: `BH = {p, q, r}`

| Paso | BH actual | Conjunto de conflictos | Seleccionada | Nueva inferencia |
|---|---|---|---|---|
| 1 | {p, q, r} | {R1, R2} | R1 | s |
| 2 | {p, q, r, s} | {R2, R4} | R2 | t |
| 3 | {p, q, r, s, t} | {R3, R4} | R3 | u |
| 4 | {p, q, r, s, t, u} | {R4} | R4 | v |

BH final: `{p, q, r, s, t, u, v}`

**Ventajas:** natural para monitoreo y diagnóstico incremental; genera todas las consecuencias de los hechos iniciales; útil con muchos hechos de entrada.
**Cuidado:** puede disparar reglas irrelevantes; depende de una buena estrategia de conflictos.

### 2.5 Encadenamiento hacia atrás (guiado por metas)

**Cuándo se usa:** se parte de una meta que se desea demostrar; se buscan reglas cuyo consecuente es la meta; útil para diagnóstico, consulta y prueba de hipótesis; reduce exploración innecesaria.

**Ciclo básico**
1. Fijar objetivo.
2. Buscar reglas que lo concluyan.
3. Colocar sus antecedentes en la pila de metas.
4. Comprobar si cada antecedente es verdadero en la base de hechos.
5. Si falta un antecedente, convertirlo en subobjetivo y repetir.
6. Si todos son verdaderos, disparar la regla y confirmar la meta.

**Ejemplo** (mismas reglas, BH = {p, q, r}, objetivo `v`)
1. ¿v ∈ BH? No → buscar reglas que concluyan v.
2. R4: `s ∧ r → v`. r ∈ BH, s no → nuevo subobjetivo s.
3. R1: `p ∧ q → s`. p y q ∈ BH → se dispara R1, se agrega s. BH = {p, q, r, s}.
4. Volver a R4: s y r ∈ BH → se dispara R4 y se concluye v. BH final = {p, q, r, s, v}.

**Fortalezas:** se enfoca en la meta; evita inferencias innecesarias; útil con pocas metas críticas.
**Cuidado:** requiere metas bien formuladas; con muchas alternativas puede implicar backtracking.

### 2.6 Comparación hacia adelante vs. hacia atrás

| Aspecto | Hacia adelante (directo) | Hacia atrás (inverso) |
|---|---|---|
| Punto de partida | Hechos conocidos en la memoria de trabajo | Meta o consulta a demostrar |
| Dirección | De los hechos a nuevas conclusiones | De la meta a los hechos que la apoyan |
| Mejor uso | Obtener todas las conclusiones posibles | Verificar una meta específica |
| Riesgo principal | Muchas conclusiones irrelevantes (explosión de búsqueda) | No encontrar la meta si faltan hechos o reglas |
| Tipo de búsqueda | Impulsada por datos (data-driven) | Impulsada por metas (goal-driven) |
| Resultado esperado | Todas las conclusiones deducibles | Si la meta es verdadera y cómo se justifica |

**Ventajas de los sistemas de producción:** modularidad, claridad de reglas, facilidad de actualización, trazabilidad del razonamiento, separación entre conocimiento y control.
**Desventajas:** mantenimiento difícil en sistemas grandes, conflictos entre reglas, explosión combinatoria, dependencia de una buena representación, posible ineficiencia.

### 2.7 Taller resuelto conceptualmente

Reglas:
1. Si a y b entonces c
2. Si b y c entonces f
3. Si h y f entonces g
4. Si a entonces g
5. Si k y j entonces m
6. Si c y f entonces h
7. Si g y f entonces i
8. Si h e i entonces j

Hechos iniciales: a y b verdaderos.

Mapa (hacia adelante): a, b →R1→ c; b, c →R2→ f; c, f →R6→ h; a →R4→ g; g, f →R7→ i; h, i →R8→ j; (k, j →R5→ m, pero k no está disponible).

**Conclusión:**
- **j sí es verdadera**: se demuestra desde a y b mediante c, f, h, g e i.
- **m no puede demostrarse**: R5 requiere k y j; j se obtiene, pero k no está disponible.

El problema puede resolverse con ambos encadenamientos; aquí se ilustró la ruta hacia adelante.

### 2.8 Sistemas expertos: fundamentos y componentes

**¿Qué es?** Software de apoyo a la toma de decisiones que busca imitar el razonamiento de un experto humano en un dominio. Simula procesos de aprendizaje, memorización, razonamiento, comunicación y acción del experto. Pertenece al paradigma de herramientas basadas en conocimiento.

**Propósito:** capturar el conocimiento experto → almacenarlo en una base de conocimientos → procesarlo mediante reglas o heurísticas → ofrecer recomendaciones o conclusiones.

**Actores clave**
- **Experto del dominio**: aporta el conocimiento especializado.
- **Ingeniero del conocimiento**: elicita, estructura y formaliza ese conocimiento.
- **Usuario final**: plantea consultas y usa las conclusiones.

**Componentes:** usuario ↔ interfaz de usuario ↔ motor de inferencia, conectado con la base de conocimientos (reglas, hechos, heurísticas, marcos), la memoria de trabajo (hechos del caso, nuevos hechos y conclusiones), el módulo de explicación y el módulo de actualización de conocimientos.

- **Base de conocimientos**: axiomas (hechos, verdades, representaciones) y teoremas (hechos derivados lógicamente).
- **Motor de inferencia**: mecanismo para resolver problemas; conocimiento general, no específico del dominio.

**Shell (concha):** la estructura genérica que queda cuando se extrae el conocimiento de la base de conocimientos. Incluye el motor de inferencia y herramientas de soporte, pero no el conocimiento del dominio.

**Formas de representación:** reglas SI–ENTONCES, hechos, heurísticas, marcos / estructuras semánticas.

**Idea central:** el conocimiento experto debe estructurarse para que sea almacenable y procesable por un programa, normalmente en dominios limitados.

**Ejemplo ESIA Expert System**
- Hechos: recursos de información, calificación de riesgo, calificación de controles.
- Reglas: guías y decisiones en la evaluación de riesgos y controles.
- Motor: selección de reglas y mecanismo de resolución de conflictos.

### 2.9 Ejemplo de inferencia en cadena (tormenta)

Reglas:
- R1: SI la temperatura es mayor a 30° ENTONCES el tiempo es caluroso.
- R2: SI la humedad relativa es mayor que 65% ENTONCES la atmósfera está húmeda.
- R3: SI el tiempo es caluroso y la atmósfera está húmeda ENTONCES se va a formar una tormenta.

Memoria de trabajo inicial: temperatura 32°, humedad > 65%.
R1 → "el tiempo es caluroso"; R2 → "la atmósfera está húmeda"; R3 → "se va a formar una tormenta".

Una sola regla aporta poco; un conjunto encadenado alcanza una conclusión significativa.

# Reglas con prioridad (mayor número, mayor prioridad)
reglas = [
    {"nombre": "Diagnóstico Grave", "prioridad": 10,
     "condicion": lambda datos: datos.get("fiebre_alta") and datos.get("dolor_pecho")},
    {"nombre": "Diagnóstico Moderado", "prioridad": 5,
     "condicion": lambda datos: datos.get("fiebre_alta") or datos.get("tos")},
    {"nombre": "Diagnóstico Leve", "prioridad": 1,
     "condicion": lambda datos: True},  # Diagnóstico por defecto
    {"nombre": "Posible Resfriado", "prioridad": 3,
     "condicion": lambda datos: datos.get("tos") and datos.get("dolor_garganta")},
    {"nombre": "Posible Gripe", "prioridad": 7,
     "condicion": lambda datos: datos.get("fiebre_alta") and datos.get("dolor_muscular")},
]

def motor_inferencia(datos):
    # Filtrar reglas que aplican
    reglas_activas = [r for r in reglas if r["condicion"](datos)]
    # Resolver conflicto eligiendo regla con mayor prioridad
    if reglas_activas:
        regla_seleccionada = max(reglas_activas, key=lambda r: r["prioridad"])
        return regla_seleccionada["nombre"]
    return "Sin diagnóstico"

### 2.14 Motor de inferencia – Resolución de conflictos, Versión 1

Versión anterior (en la presentación), que obtiene los antecedentes de los **parámetros de la lambda** `condicion` y genera el hecho nuevo a partir del nombre de la regla:

```python
def motor_inferencia_avanzado(datos_iniciales, reglas):
    hechos = set(datos_iniciales.keys())  # Convertir datos iniciales a hechos
    hechos_nuevos = set()
    reglas_disparadas = set()
    while True:
        reglas_aplicables = []
        for i, regla in enumerate(reglas):
            # a) No repetir reglas ya disparadas
            if i not in reglas_disparadas:
                # Verificar si la regla se aplica (todos los antecedentes son hechos)
                # Extraer los nombres de los parámetros de la función lambda
                import inspect
                antecedentes = set(inspect.signature(regla["condicion"]).parameters.keys())
                # Verificar si todos los antecedentes están presentes en los hechos actuales
                if antecedentes.issubset(hechos):
                    reglas_aplicables.append((i, regla))

        # Mostrar el conjunto de conflictos (reglas aplicables)
        print("\nConjunto de conflictos (Reglas aplicables):")
        if reglas_aplicables:
            for _, regla in reglas_aplicables:
                print(f"- {regla['nombre']}")
        else:
            print("- Ninguna")
        if not reglas_aplicables:
            break  # No hay reglas aplicables, detener la inferencia

        # ***** Resolver conflicto *****
        # b) Seleccionar aquellas con mayor número de antecedentes
        reglas_aplicables.sort(
            key=lambda item: len(inspect.signature(item[1]["condicion"]).parameters.keys()),
            reverse=True)
        # c) Seleccionar aquellas que tengan antecedentes recién agregados
        # (Esta parte requiere un seguimiento de qué hechos son nuevos,
        # IMPLEMENTAR ESTA regla para resolución de conflictos)
        # d) Al azar (si hay empate después de las reglas anteriores)
        # En este ejemplo, si hay reglas con el mismo número de antecedentes,
        # se seleccionará la primera en el orden después de la clasificación.

        # Seleccionar la primera regla aplicable después de la resolución de conflictos
        indice_regla_seleccionada, regla_seleccionada = reglas_aplicables[0]
        print(f"\nRegla seleccionada: {regla_seleccionada['nombre']}")

        # Disparar la regla y agregar nuevos hechos
        reglas_disparadas.add(indice_regla_seleccionada)
        # Se asume que la regla "agrega" un nuevo hecho basado en su nombre
        nuevo_hecho = regla_seleccionada["nombre"].replace(" ", "_").lower()
        if nuevo_hecho not in hechos:
            hechos_nuevos.add(nuevo_hecho)
            hechos.add(nuevo_hecho)
            print(f"Regla disparada: {regla_seleccionada['nombre']}. Nuevo hecho agregado: {nuevo_hecho}")
    return list(hechos)
```

**Diagrama de flujo (encadenamiento hacia adelante)**
1. Inicio → entradas: `datos_iniciales` (diccionario) y `reglas` (lista).
2. Inicializar: `hechos` = claves de `datos_iniciales`; `hechos_nuevos` = ∅; `reglas_disparadas` = ∅.
3. Encontrar reglas aplicables (no disparadas y con todos sus antecedentes en `hechos`).
4. Mostrar conjunto de conflictos. ¿Hay reglas aplicables? No → Fin (retornar hechos).
5. Sí → resolver conflicto (ordenar por mayor número de antecedentes; en empate, la primera).
6. Mostrar regla seleccionada → dispararla (agregar índice a `reglas_disparadas`; agregar consecuentes nuevos a `hechos` y `hechos_nuevos`).
7. Mostrar resultado → ejecutar acción opcional → volver al paso 3.

**Estructuras de datos:** `hechos` (conocidos e inferidos), `hechos_nuevos` (agregados en cada iteración), `reglas_disparadas` (índices ya ejecutados), `reglas_aplicables` (reglas cuyo antecedente está en hechos).

## 3. Taller fuera de aula

**Valor:** 4 puntos. Grupos de hasta 3 personas.

Usando el código del motor de inferencia modificado, implementar el sistema experto que permita apoyar la toma de decisiones en el siguiente dominio (fallas de red).

**Adicional (opcional):** incluir una interfaz gráfica, para reemplazar una nota de talleres.

| Causa (Antecedente) | Falla detectada (Consecuente) |
|---|---|
| El equipo no recibe dirección IP y el servidor DHCP no responde | Falla de asignación de IP por DHCP |
| Alta latencia y pérdida de paquetes en múltiples nodos | Congestión de red o saturación de ancho de banda |
| Dirección IP duplicada detectada en dos dispositivos | Conflicto de IP |
| El router no responde a pings y no hay acceso a internet | Falla en el router principal |
| El switch no reenvía paquetes entre segmentos | Falla en el switch o en la configuración de VLAN |
| El usuario no puede acceder a recursos compartidos, pero tiene conexión a internet | Problema de resolución DNS o configuración de red local |
| Señal inalámbrica débil y desconexiones frecuentes | Interferencia electromagnética o distancia excesiva al AP |
| El firewall bloquea puertos necesarios para servicios internos | Falla de configuración en reglas del firewall |
| El cable de red está desconectado o dañado | Falla física de conexión |
| El sistema presenta lentitud tras actualización de drivers de red | Incompatibilidad o error en el controlador de red |
| Se detecta tráfico anómalo y múltiples intentos de conexión desde IPs externas | Posible ataque de red (DoS, escaneo de puertos, etc.) |

### Flujo de referencia: diagnóstico de fallas en computador

1. Inicio.
2. Mostrar bienvenida y explicación.
3. Identificar síntomas.
4. Preguntar por cada síntoma (si/no): `¿conexion_lenta?`, `¿sin_internet?`, `¿pantalla_azul?`, … (todos los síntomas).
5. Recopilar respuestas.
6. Diagnosticar problemas.
7. ¿Problema identificado?
   - Sí → mostrar diagnóstico y solución.
   - No → mostrar mensaje de error y sugerir consulta con técnico.
8. Fin.
